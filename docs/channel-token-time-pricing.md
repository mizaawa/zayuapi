# 渠道 Token（峰谷）定价及验收口径

- 渠道和账号统计规则中的 `token_peak` 是**配置模式**。实际请求仍走 Token 结算并记录 `billing_mode=token`，原有日志筛选不变。分组单独定价的优先级不变。
- 兜底输入和输出单价必须显式填写，允许写 0。每个时间段至少填写一项单价，可覆盖文本输入、输出、缓存写、缓存读、图片输入、图片输出。区间的空字段继承兜底卡，不会把空值当成 0。界面为每百万 Token 单价，API 和数据库为每 Token 单价。
- 上海时间，精确到分钟，区间左闭右开。`23:30–02:15` 支持跨午夜：02:14 仍在区间内，02:15 已离开。相邻区间可以共用边界，不允许任何覆盖同一分钟的区间，也不能以相同起止时间表示全天。全天同价只需填写兜底价。

## 金额核对

| 路径 | 验收条件 |
| --- | --- |
| 普通、流式及 WebSocket Token 请求 | 使用既有请求时刻选择价卡；跨峰谷边界不因异步写账而二次定价。已选择的价格继续走原有上下文、服务档位和分组倍率计算。 |
| 图文及缓存 | 图片 Token 是对应输入或输出总量的子集，不能重复累加。显式图片输入价 0 与未配置不同。分别检查 `input_cost`、`image_input_cost` 及合计。 |
| 生图预扣与结算 | 请求已有定价时刻时应沿用。保留预扣时采集的 Token 价卡，在收据结算时按实际使用量计算；不要用结算当时的上海时间重选价卡。 |
| 上游统计与用户扣费 | 单独的上游统计规则和“采用渠道定价”按相同时间边界选卡，不要再乘用户分组倍率。显式免费规则不能落到收费的模型目录。 |
| 按次、图片、视频与历史订单 | 不得把 Token 单价当按次、每张或每秒单价；历史账单不回算。批量任务已有定价快照时优先使用快照。 |
| 余额、订阅、重试及退款 | 发布前须通过现有的幂等结算、重试、配额、媒体恢复和集成测试；费率单元测试不能替代这些检查。 |

文本定价准入时保留渠道及目录价表版本。管理员在请求中途修改或删除价格，不会改变该请求的用户扣费和上游成本；新请求及 WebSocket 后续轮次重新取价。快照只传递给计费任务，不冻结路由限制，不更改历史账单。生图异步恢复使用独立的持久化预扣快照。如果仍出现 `pricing_missing_record_zero_cost`，这不是管理员配置的免费，应按请求核对；绕过定价准入的内部调用不能依赖接单快照。

短暂读不到渠道价格时，文本网关不改用目录价：接单失败可重试，不转发、不扣费。只有成功读取并确认没有覆盖价，才会按正常顺序回退。

普通文本结算先将原始扣费指令和用量快照写入 `pending_usage_settlements`，再用一个 PostgreSQL 事务完成幂等登记、扣款、用量明细及待结算记录删除。数据库超时或进程重启后，恢复任务使用相同的请求 ID 和报价，不重新取价，不重复扣款。长期存在的待结算记录和 `usage_settlement.recovery_failed` 需要排查，不能当作免费；不要手工删除待结算记录或幂等键。媒体预扣继续沿用独立恢复流程。若数据库持续不可写，连待结算记录都没有保存成功，仍需对照上游请求及应用错误日志排查。

### 可复核的端到端样例

测试账号初始余额为 $10，每次上游调用返回 1,000 个输入 Token 和 100 个输出 Token。兜底价为输入 $2、输出 $5（每百万 Token），峰谷时段覆盖为输入 $0、输出 $7。分组倍率为 2；上游统计使用渠道价，账号倍率为 1。

| 请求 | 用户实扣 | 上游成本 |
| --- | ---: | ---: |
| 兜底价 | $0.0050 | $0.0025 |
| 峰谷时段，输入免费 | $0.0014 | $0.0007 |
| 时段内接单、时段外完成 | $0.0014 | $0.0007 |
| 兜底价，首次 429、重试成功 | $0.0050 | $0.0025 |
| 按兜底价接单，响应前删除渠道价 | $0.0050 | $0.0025 |
| 明确设置输入和输出均免费 | $0 | $0 |

本地发布镜像中，这六笔应对应 6 条用量、6 个幂等键、1 条免费记录；总扣款 $0.0178，余额 $9.9822，待结算数为 0。该对账使用真实 PostgreSQL 和 Redis、可控上游响应。若进程在首次持久化待结算记录前退出，恢复任务不能重建从未写入的记录，仍需核对上游。

## 经营趋势

图表使用站点会计时区的持久化日汇总。桌面展示最近 15 个自然日，手机展示最近 7 个；日汇总已经包含账号倍率，不能再次相乘。后台清理明细不会删去这些日汇总。系统未记录过的历史汇总不能由这次升级还原。
