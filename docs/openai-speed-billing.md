# OpenAI 分组的速度档位和计费

在「分组管理」的新建或编辑窗口配置。两个开关彼此独立：

| 设置 | 默认 | 生效范围 |
| --- | --- | --- |
| Fast/UltraFast 单独倍率计费 | 关闭；预设分别为 2 和 6 | 开启后，token 实付按普通模型价 × 分组/用户倍率 × 对应速度倍率计算。高峰倍率照常叠加。两个倍率都必须在 0.1–100 范围内。 |
| 强制开启 Fast 模式 | 关闭 | Fast 发送 `service_tier: priority`，UltraFast 发送 `service_tier: ultrafast`。客户端不传档位或选择其他档位，都不能改变分组的选择。 |

强制模式只决定发给上游的档位。单独倍率关闭时，强制 Fast、UltraFast 均按普通模型价向用户收费：不取已保存的速度倍率，也不取模型的加速价。分组或用户倍率、高峰等普通计费规则照常生效。单独倍率开启时，按强制档位对应的倍率向用户收费。上游成本独立核算。

未强制时，沿用已有的客户端选档与上游降档计费规则。与账号策略冲突或上游不支持时，不自动重发为普通档。此修复从 v0.2.230 起对新结算生效，不会重算已结算账单。

Responses（含 compact、流式、WebSocket 各轮）、Chat Completions 和 Messages 到 OpenAI 的协议转换均在出站时处理。OAuth 图片转 Responses 时使用同样的出站规则；按张、按次计价不乘速度倍率。原生图片、向量和计数接口没有通用的生成速度档位。Live 无法在网关逐轮保证该约束，强制分组不能使用 Live。

用户和管理员的使用记录在模型名旁显示 `Fast ×2` 或 `UltraFast ×6` 等标签。倍率取自当次 token 账单；关闭独立计费、普通请求、非 token 账单和旧记录不显示。修改分组预设不会改变历史标签。模型广场展示的是当前预设，不是历史账单。

WebSocket 后续轮次复用与 HTTP 相同的认证缓存，核对本轮密钥、用户和分组。密钥撤销、换组、权限状态变化或读取失败时拒绝继续发送，客户端须重新连接。单轮转发和结算共用该轮的定价快照。

升级提示：旧 Antigravity OAuth 不再内置客户端密钥。仍使用此旧集成的部署需显式设置 `ANTIGRAVITY_OAUTH_CLIENT_SECRET`；OpenAI 分组不受影响。不要将实际值提交到版本库。
